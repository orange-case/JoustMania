# Use Case: Play Swapper

## Overview

**Use Case ID:** UC-024
**Use Case Name:** Play Swapper
**Primary Actor:** Player
**Goal:** Be on the team everyone ends up on, without being the last one swapped
**Status:** Tested
**Requirements:** FR-024, FR-027, FR-030, FR-033

The game lifecycle is the base of [UC-020](UC-020.md) (BR-005 to BR-009 there); this use case states only the Swapper delta (BR-006) and its own flows and rules.

## Preconditions

- A Swapper game was started with at least three players, the mode's minimum (UC-010 BR-001); always two teams.

## Main Success Scenario

1. System splits players into two teams.
2. A player whose movement exceeds the threshold switches to the other team (`player_swapped`) and gets a grace period of `death_grace_period_seconds`. The controller LED shows one FLASH, then the new team colour; the base death effect is not sent, and the player stays alive in the `player_alive` gauge and the alive aggregate. A swap is no elimination (BR-005).
3. When every player is on one team, System publishes `swapper_winner` (team, winners, excluded serial): the last swapped player does not win.
4. System publishes `player_analytics` for each player (when `analytics.enabled` is on; UC-041 BR-006) and `game_ended`.

## Alternative Flows

### A1: Disconnect

**Trigger:** A player's controller disconnects during the game (step 2), including warm-up
**Flow:**

1. System eliminates the player: the player is not swapped, stays out of the game and gets the base death effect; its `game.player` span ends with `player_eliminated` (`reason` = `controller_disconnect`).
2. The player no longer counts for either team: team counts, convergence and the winners leave it out (it stays in the session's player list).
3. A disconnect that arrives while the player's own swap is still running (an `eliminate_player` swap, BR-002) also eliminates it: the swap does not finish, so no new team colour, no `player_swapped` and no swap sound. When the disconnect lands later in the swap (while the new colour is written, during the `player_swapped` publish or the swap sound), what was already sent stays, the rest is skipped, and the swap takes the player out when it resumes: not alive, its span ends with `player_eliminated`, base death effect.
4. System runs the win check at once. When only one team is left, the use case continues at step 3; when no player is left, nobody wins.
5. Otherwise the game continues at step 2.

### A2: Instructions on

**Trigger:** The host has switched spoken instructions on (`game_instructions`, FR-014, the pad's K6, UC-015 BR-011) when the game starts (step 1)
**Flow:**

1. System runs the base instructions flow (UC-020 A5) with the `Swapper-instructions` clip.
2. Use case continues at step 2.

## Postconditions

### Success Postconditions

- The winners are in the event stream; the session is ENDED.

### Failure Postconditions

- `game_error` ends the session.

## Business Rules

### BR-001: Last swap excluded

The player whose death completed the swap is excluded from the winners. An eliminated player (A1) is never the excluded one. An elimination clears the last swap only when it completes the convergence itself: then nobody is excluded, so the winners list is never empty (D2). When the teams had already converged by the last swap (an `eliminate_player` swap whose win check has not run yet), the last swapped player stays excluded, unless it is the only player left on its team.

### BR-002: Interventions

The agent's `eliminate_player` swaps the player like a motion death (step 2, `death.reason` = `agent_intervention`); it does not remove the player (D1). `revive_player` is denied for Swapper by the intervention capability matrix (`interventions.py`), so an eliminated player (A1) never comes back.

### BR-003: Outcome

Swapper uses the base `run()`; its outcome, force-end and latch are the base rules UC-020 BR-006 and BR-007 with the values of BR-006 here. On top of the base, a force-end shows no grey on the last swapped player, and a swap in flight when the game ends or the win is latched (BR-004) is cut short: a swap that is still pausing does not finish (no team colour, no `player_swapped`, no swap sound, no death effect over the end effects); a swap whose new team colour is being written keeps the colour and the new team, but publishes no `player_swapped` and plays no swap sound.

### BR-004: Win latch

The win is latched as in UC-020 BR-007; the Swapper latch freezes the winning team, the winners and the excluded player, and the end-of-game step uses only that snapshot, so `game_ended` names the same team as `swapper_winner`. Once latched, an `eliminate_player` kill no longer swaps or eliminates anyone: the kill gate declines the kill before any death bookkeeping (UC-030 step 9), and the `eliminate_player` is recorded as blocked `eliminate_refused` (UC-040 A22). A kill already in flight when the win is latched or the game is force-ended is declined by the gate's second check, right before the bookkeeping: no death is counted (its explosion may already have played), and only a player whose disconnect was marked before the latch is still eliminated (A1). A disconnect is ignored earlier, by `_handle_disconnect`, so the gate never sees it. When every remaining player was eliminated (A1), the latch holds no winner.

### BR-005: Only an eliminated player is an elimination

The base rule is UC-020 BR-008: a swap, also an `eliminate_player` swap (BR-002), keeps the player in the game and is no elimination; a player eliminated by a disconnect (A1) is one. Swapper delta: the disconnected player gets its order once, when it is taken out (a disconnect death carries `death.eliminated` true; a disconnect during the player's own swap, A1 step 3, records the order at the disconnect while the player is not yet repainted, else when the swap resumes, with no second death). Swapper's `player_death` keeps the team attributes (`team`, `team_eliminated`) next to `death.eliminated`. No order is recorded once the game has stopped running.

### BR-006: Delta from the base lifecycle

| Row | Swapper |
|---|---|
| Win condition | every player still in the game on one team (step 3); the last swapped player does not win (BR-001); everyone eliminated (A1): nobody wins |
| Teams | always two teams (step 1); a death swaps the player to the other team (step 2) |
| Thresholds | the tempo-driven thresholds (UC-030) |
| Start cues | the team colours, the countdown |
| Result event and end cues | `swapper_winner` (team, winners, excluded serial) + rainbow + team victory voice; grey on the last swapped player |
| No-winner value in `game_ended` | `winning_team` `none` |
| Instruction clip (A2) | `Swapper-instructions` |
| Streamed intro | no |
| `run()` | base |
| Mode grace | `death_grace_period_seconds` after a swap (step 2) |
| Eliminations | a disconnect only (A1, BR-005); a swap is none |
