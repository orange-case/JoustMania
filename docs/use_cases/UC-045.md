# Use Case: Stop the Agent with Flags

## Overview

**Use Case ID:** UC-045
**Use Case Name:** Stop the Agent with Flags
**Primary Actor:** Operator
**Goal:** Stop, or make inert, every in-game agent effect, the experiment loop and every paid model call immediately and reversibly
**Trigger:** Operator wants the agent to stop acting at once (for example a misbehaving backend, a cost concern, or a talk beat)
**Status:** Tested
**Requirements:** FR-042, FR-049, FR-050, FR-051, FR-066, NFR-050, NFR-052, C-002, C-030, C-032, C-034
**Planned:** FR-152 (#1788, Implemented; stays here until a UC-045-tagged test covers it)

## Preconditions

- The agent runs: `enabled` is `watch` or `act` (`enabled` has three states, `off` / `watch` / `act`; the shipped baseline is `watch`, the CI baseline `off`).

## Main Success Scenario

1. Operator runs `scripts/agent-killswitch.sh off`: it writes `enabled` = `off` as a stack-wide value on the flag service, in memory only. It is a write, never a clear: clearing the value would return the baseline `watch` and leave the agent running.
2. flagd serves `enabled` = `off` to the agent within the write-propagation bound (NFR-050), with no file edit and no agent restart.
   The agent sees the flip on its next read: it evaluates without a resolver cache ([flags.md §1.3](../specs/flags.md#13-reload-semantics)).
3. On its next decision cycle the agent stops evaluating and makes no decide call; instead it emits an `agent.disabled` span, at most one per `decision.throttle_seconds`.
4. Any remote answer still in flight is discarded on landing (`kill_switch`, [UC-040](UC-040.md) A6).
5. On the next experiment tick (`experiment_tick_seconds`, default 30 s) the agent aborts running experiments and force-ends any pattern game still in flight ([UC-046](UC-046.md) A12). On the same tick it removes every real-default overlay an autonomous promotion wrote (writer `promotion` on the flag service, also from before an agent restart; its `DELETE` carries `?if_writer=promotion`, so another writer's overlay is never removed, [UC-043](UC-043.md) A18), stops each promotion's re-watch and journals the revert (reason `kill_switch`, [UC-043](UC-043.md) A1). A promotion write in flight when the tick starts lands first and is reverted by that tick; a promotion that read its flags before the tick does not write after it. The tick repeats while `enabled` is off, so a failed revert is retried (journaled once, [UC-043](UC-043.md) A1).
6. From the next game end, the retro is capture-only and the experiment proposer does nothing ([UC-042](UC-042.md) A8, A5).
7. Later, operator runs `scripts/agent-killswitch.sh act` (or `watch`) to resume: it sets `enabled` to that state as a stack-wide value on the flag service, held in memory only, so a flag-service restart returns the agent to the baseline `watch` ([UC-053](UC-053.md) A1).

## Alternative Flows

### A1: Observe without acting

**Trigger:** Operator sets `enabled` to `watch` instead (step 1): `scripts/agent-killswitch.sh watch`, or the pad's `AGENT` row 1 ([UC-016](UC-016.md) BR-012; FR-051).
**Flow:**

1. The agent keeps deciding and spanning, but writes no intervention (`decision.not_applied_reason=watch`, [UC-040](UC-040.md) A11) and the coordinator applies none ([UC-040](UC-040.md) BR-004). It writes no experiment arm either: on the next experiment tick it tears down running experiments (`agent watch: arm writes need enabled=act`), and the proposer still drafts but writes nothing (skip reason `agent_watch`). Watch is not a stop: the real-default overlays of autonomous promotions are not reverted (step 5 runs only at `off`), and no new autonomous promotion is made.
2. Use case ends.

### A2: Narrow the allow-list

**Trigger:** Operator sets `interventions_allowed` to `none` instead (step 1); the operator pad is the host's way to do the same ([UC-015](UC-015.md) BR-002 to BR-004)
**Flow:**

1. The agent keeps running, but no intervention passes the agent or the coordinator, and on a remote backend the agent makes no decide call, so no model is called and no budget is charged ([UC-040](UC-040.md) BR-005, A14).
2. Use case ends.

### A3: Flagd unreachable

**Trigger:** The agent cannot read flags (step 3): flagd is unreachable, or its in-process provider is not READY: no first flag sync yet, or the sync stream is lost (STALE / ERROR) until flagd sends again ([flags.md §1.1](../specs/flags.md#11-clients))
**Flow:**

1. `enabled` fails closed (`off`) and `interventions_allowed` resolves to an empty list; `experiments_enabled` and `experiment_dynamic_enabled` fail closed too (no env fallback), so the experiment loop and the proposer stop on either gate.
2. Use case ends.

### A4: Stop infrastructure remediation (retired)

**Trigger:** None: the controller-backend rollout, its infrastructure loop and its gates `rollout_enabled` and `remediation_allowed` are removed ([UC-050](UC-050.md), [UC-051](UC-051.md), Obsolete). The ID is kept so it is not reused (step 1)
**Flow:**

1. Use case ends.

### A5: Flag service refuses or cannot be reached

**Trigger:** the flag service refuses the `off` value (for example `503 no_sync_stream` while flagd is not connected, [UC-053](UC-053.md) A7) or does not answer within the script's 5 s deadline (NFR-052) (step 1)
**Flow:**

1. The script prints that the flag service did not take the change and the fallback brake: stop the agent container (`docker stop joustmania-agent`); the game keeps running without the agent. It exits non-zero.
2. `enabled` keeps its state, and flagd keeps serving it, until the operator applies the brake or a retry succeeds.
3. Use case ends.

### A6: Resume refused

**Trigger:** the flag service refuses the `act` or `watch` value or cannot be reached (step 7)
**Flow:**

1. The script prints the error and exits non-zero.
2. Use case ends; `enabled` stays `off`.

## Postconditions

### Success Postconditions

- While `enabled` is `off`, until step 7, no new agent effect reaches any game: from step 3 the agent makes no decide call and writes no intervention, from step 5 it runs no experiment, and no real-default overlay an autonomous promotion wrote survives: the kill-switch revert is its last real-default write (step 5), and from step 6 it makes no post-game model call. State interventions already written for a live game stay until that game ends (they are dropped with its scope, [UC-053](UC-053.md) BR-003).
- After step 7 the agent decides again from its next decision cycle.
- (Retired: the infrastructure rollout this postcondition kept apart from `enabled` is removed, A4.)
- The settings that limit the agent (autonomous promotion, code improvement, the remote-call ceiling) stay operator-owned and are never agent-writable; the remote-call cap is `min(AGENT_LLM_MAX_REQUESTS_PER_MINUTE, llm.max_requests_per_minute)`; this use case's flow is unchanged (FR-152).

### Failure Postconditions

- The agent can do no more than before the operator acted: a refused or failed change leaves `enabled` as it was (A5, A6).

## Business Rules

### BR-001: Independent intervention gates

`enabled` (the agent state) and `interventions_allowed` (permission) are separate flags; either can stop interventions. `enabled` = `off` stops the agent, `watch` lets it decide and record while it writes nothing that changes a game (no intervention, no experiment arm, no autonomous promotion), and only `act` writes; the allow-list is the same at `watch` and `act`, so a watched decision shows what the level would allow. Since #2800 `enabled` is the one human stop: every stop surface (the pad's K5 hold and `AGENT` row 1, [UC-015](UC-015.md) BR-002, and this script) writes `enabled` alone, and the game coordinator reads `enabled` on its own and applies no intervention unless it is `act` ([UC-040](UC-040.md) BR-004), so a stop holds even against a write that reaches the flag service after it. The experiment loop also needs `experiments_enabled`.

### BR-002: Post-game model calls obey the kill switch

See [UC-042](UC-042.md) BR-002 and A5 (the proposer, including a flip during its model call) and UC-042 A8 (the retro): with `enabled` off neither makes a model call (FR-042, FR-066).
