# Use Case: Play a Hidden-Role Game

## Overview

**Use Case ID:** UC-022
**Use Case Name:** Play a Hidden-Role Game (Traitor, Werewolf)
**Primary Actor:** Player
**Goal:** Win for your secret side
**Status:** Tested
**Requirements:** FR-022, FR-027, FR-030, FR-033

The game lifecycle is the base of [UC-020](UC-020.md) (BR-005 to BR-009 there); this use case states only the Traitor and Werewolf delta (BR-007) and their own flows.

## Preconditions

- A Traitor or Werewolf game was started with at least the mode's minimum players: four for Traitor, three for Werewolf (UC-010 BR-001).

## Main Success Scenario

1. For Traitor, System builds teams (the `num_teams` flag, default 2, as the menu sends it; only when no team count is given: 2 teams below 9 players, otherwise up to 3) and picks traitors per the `traitor.count_tiers` flag (≤ 5 players: 1, ≤ 8: 2, ≤ 11: 3, else n / 3), capped at ⌊(n − 1) / 2⌋ so loyal players outnumber traitors: at least 1 from 3 players, and a 2-player game has no traitor.
2. System gives each traitor a secret team different from its visible team, opens the gameplay stream and runs a 5 s `traitor_signal` phase (`traitor_signal_start` / `traitor_signal_end`): each controller pulses its visible team colour and then keeps it as its base colour, and each traitor feels a rumble (BR-003).
3. Players play; deaths use the normal thresholds (UC-030).
4. When only one secret team has players alive, System publishes `traitor_winner` (team, winners, traitor and loyal winners), shows the winners a rainbow with the traitor win voice, and publishes `player_analytics` for each player (when `analytics.enabled` is on; UC-041 BR-006) and `game_ended` with `winning_team` (the secret team index, `none` when no team won), `traitor_count`, `outcome` and, after a force-end, `reason` (BR-007, UC-020 BR-007).

## Alternative Flows

### A1: Werewolf

**Trigger:** Mode is Werewolf (step 1)
**Flow:**

1. System picks `max(1, int(n × werewolf.werewolf_fraction))` werewolves (default fraction 0.44); everyone is yellow.
2. System opens the gameplay stream and runs a `werewolf_intro` over it: all controllers yellow and a rumble to the werewolves only; frames that arrive during the intro are read and discarded (only disconnects are kept, as in UC-021 A1). After the countdown System primes the EMA (the startup guard, UC-030 BR-003) and reveals the werewolves (light blue) `werewolf.reveal_time_seconds` (default 35 s) after gameplay starts, with `werewolf_reveal`. A reveal timer that fires once a side has won (the win hold) or after the game stopped reveals nothing and publishes no `werewolf_reveal` (BR-006). A reveal LED write that fails on a gameplay stream that has died is skipped: the other werewolves are still revealed, and the reopened stream restores the light blue (UC-030 BR-006, #2022). Event order: `game_starting` → `players_initialized` → `werewolf_intro_start` / `werewolf_intro_end` → `countdown_start` / `countdown_end` → `game_started` → `werewolf_reveal` (Werewolf publishes `game_started` after the countdown, the base modes before it).
3. Werewolves use fixed thresholds from `werewolf.thresholds` that ignore tempo and agent factors; humans use the normal slow thresholds (BR-001).
4. When all humans or all werewolves are dead, System publishes `werewolf_winner`, `player_analytics` for each player (when `analytics.enabled` is on; UC-041 BR-006) and `game_ended`.
5. Use case ends.

### A2: Tie

**Trigger:** No secret team survives (step 4), or no human and no werewolf survives (A1 step 4)
**Flow:**

1. System publishes `game_tie`; Werewolf publishes no `werewolf_winner` in this case.
2. Use case ends.

### A3: Instructions on

**Trigger:** The host has switched spoken instructions on (`game_instructions`, FR-014, UC-012 A3) when the game starts (step 2, A1 step 2)
**Flow:**

1. System runs the base instructions flow (UC-020 A5) for a streamed intro: Traitor plays `Traitor-instructions` after the `traitor_signal` phase, Werewolf plays `werewolf-instructions` after the `werewolf_intro`; the gameplay stream is open and drained meanwhile, and released when a force-end during the wait ends the game. In Werewolf a force-end during the `werewolf_intro` skips the clip.
2. Use case continues at step 3 (Werewolf: A1 step 3).

## Postconditions

### Success Postconditions

- The winning side (`traitor_winner` or `werewolf_winner`) or `game_tie` (A2) is in the event stream; the session is ENDED.

### Failure Postconditions

- `game_error` ends the session.

## Business Rules

### BR-001: Fixed tempo in Werewolf

By design (maintainer decision 2026-10-22, #1273), Werewolf runs without the tempo music loop: music stays at normal speed (1.0) and the slow threshold table applies all game. Werewolf runs its own `run()` around the base game loop and starts like the base `run()` (UC-020 BR-005: `game_starting`, fewer than two players refused, flag evaluation context, EMA warm-up; D-G3, moved from UC-031 BR-001 by #1500).

Flag context: the session already sets `game_kind` and the experiment (`experiment_id`, `arm`) before the game is created (`game_session.py`), so a shadow Werewolf game resolved experiments before #1273 too. The Werewolf start adds `targetingKey=game_mode`, `game_mode`, `controller_count` and `sensitivity` for the flag reads made during the game (today the shield activation mode and charge delay); it adds no experiment exposure.

### BR-002: Agent restrictions

The coordinator's mode capability matrix denies controller effects, revive and global sensitivity / difficulty interventions in Werewolf and Traitor.

Tempo and pacing interventions are accepted in Werewolf but have no effect, because Werewolf has no tempo loop (BR-001); denying them in the matrix is a product follow-up.

### BR-003: Team effects over the stream

Traitor opens the gameplay stream before the `traitor_signal` phase, so the team pulse, the persistent team colour and the traitor rumble go over it; the stream opens with every controller white. Frames that arrive during the phase and the instructions clip are discarded, with the same disconnect and reopen handling as Random Teams ([UC-021](UC-021.md) A1 step 2). The rumble goes only to the traitors. (D-G10 resolved by #1738.)

### BR-004: Root-span outcome - Obsolete (#2797)

Obsolete. The Werewolf root-span outcome and its force-end and result latch (issues #1343, #2009) are the base rules UC-020 BR-006 and BR-007; the Werewolf values are in BR-007. The ID is kept so it is not reused.

### BR-005: Traitor force-end declares no winner; the win is latched - Obsolete (#2797)

Obsolete. The Traitor force-end and win latch (issue #2003) are the base rule UC-020 BR-007; the Traitor values are in BR-007. The ID is kept so it is not reused.

### BR-006: No Werewolf reveal after the result

Once the result is latched (UC-020 BR-007) or the game has stopped running, the werewolf reveal does not go on (issue #2022): a reveal timer that fires then reveals nothing and publishes no `werewolf_reveal`, and a result latched during the reveal (the `werewolf_reveal` publish, the reveal voice, or the flash of an earlier werewolf) stops it before the next werewolf. Only the werewolves actually revealed turn light blue, are marked revealed and get the `werewolf_revealed` span event.

### BR-007: Delta from the base lifecycle

| Row | Traitor | Werewolf |
|---|---|---|
| Win condition | only one secret team has players alive (step 4) | all humans or all werewolves dead (A1 step 4) |
| Teams | visible teams (`num_teams`, default 2) and a secret team for each traitor; traitor count per `traitor.count_tiers` (step 1) | `max(1, int(n × werewolf.werewolf_fraction))` werewolves, everyone yellow; werewolves revealed light blue after `werewolf.reveal_time_seconds` (A1, BR-006) |
| Thresholds | the tempo-driven thresholds (UC-030) | werewolves: fixed `werewolf.thresholds`; humans: the slow table; no tempo loop (BR-001) |
| Start cues | 5 s `traitor_signal` (team pulse, traitor rumble; BR-003), then the countdown | `werewolf_intro` (yellow, werewolf rumble), then the countdown; `game_started` after the countdown |
| Result event and end cues | `traitor_winner` (team, winners, traitor and loyal winners) + rainbow on the winners + traitor win voice; `game_tie` (A2) | `werewolf_winner` + rainbow + win voice; `game_tie` and no `werewolf_winner` (A2) |
| No-winner value in `game_ended` | `winning_team` `none` (before #2003: `-1`); `traitor_count` always | `winner` `none`; the player spans `winning_team` `none` |
| Instruction clip (A3) | `Traitor-instructions` | `werewolf-instructions` |
| Streamed intro | yes (`traitor_signal`) | yes (`werewolf_intro`) |
| `run()` | base | own (BR-001) |
| Mode grace | none | none |
| Eliminations | every death | every death |

Force-end and latch (UC-020 BR-007): no `traitor_winner` / `werewolf_winner`, no `game_tie`, no rainbow, no win voice; the player spans end with `winner=false`. The Werewolf win check returns no result once the game is force-ended. Outcome (UC-020 BR-006): `completed` or `force_ended`.
